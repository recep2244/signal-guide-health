export interface SyncResult {
  provider: WearableProvider;

    **PKCE helpers (at top of file, not exported):**
    ```typescript
    import crypto from 'crypto';
    function generateCodeVerifier(): string {
      return crypto.randomBytes(32).toString('base64url');
    }
    function generateCodeChallenge(verifier: string): string {
      return crypto.createHash('sha256').update(verifier).digest('base64url');
    }
    ```

    **Class structure:**
    ```typescript
    export class FitbitProvider implements WearableProviderInterface {
      readonly provider = 'fitbit' as const;
      private clientId: string;
      private clientSecret: string;
      private redirectUri: string;

      constructor() {
        this.clientId = env.FITBIT_CLIENT_ID || '';
        this.clientSecret = env.FITBIT_CLIENT_SECRET || '';
        this.redirectUri = env.FITBIT_REDIRECT_URI || '';
      }
      // ... methods below
    }
    export const fitbitProvider = new FitbitProvider();
    ```

    **getAuthorizationUrl(state):** Generate a new codeVerifier each call. The codeVerifier must be stored externally (caller's responsibility — the route layer stores it in Redis). Return the authorization URL with code_challenge derived from the verifier. Since the interface requires only `state`, store the verifier in a local Map keyed by state as a fallback for single-instance dev: `private pendingVerifiers = new Map<string, string>()`. Add a method `getCodeVerifier(state: string): string | undefined` so the route layer can retrieve it.

    **syncHealthData(accessToken, since):**
    - Loop day-by-day from `since` (default: 7 days ago) to today
    - For each date (format `YYYY-MM-DD`):
      - `GET https://api.fitbit.com/1/user/-/activities/heart/date/{date}/1d.json` — extract `activities-heart[0].value.restingHeartRate` for restingHeartRate, and average of `activities-heart-intraday.dataset[].value` for avgHeartRate
      - `GET https://api.fitbit.com/1/user/-/spo2/date/{date}/all.json` — extract `value.avg` for SpO2 percentage
      - `GET https://api.fitbit.com/1/user/-/temp/skin/date/{date}.json` — extract `tempSkin[0].value.nightlyRelative` (relative to baseline; store as body temp offset) OR skip if no data
      - `GET https://api.fitbit.com/1/user/-/activities/steps/date/{date}/1d.json` — extract `activities-steps[0].value` as integer
    - All API calls: `Authorization: Bearer {accessToken}` header
    - 24-hour intraday limit: fetch only one day per request (already described above)
    - Aggregate results into `SyncResult.recordsCount`
    - **BP: explicitly do NOT fetch** — add code comment: `// Fitbit has no blood pressure sensor — BP omitted per WEAR-01 hardware gap`
    - Return SyncResult with `provider: 'fitbit'`, `success: true/false`, `syncedAt: new Date()`, and counts

    **Stub methods for interface compliance** (getHeartRate, getSleep, getActivity, getBloodOxygen, getHRV, validateWebhook, parseWebhookPayload): Implement minimally — getHeartRate/getSleep etc. can call the day-based sync internally or throw `new Error('Use syncHealthData for Fitbit')`.

    **Do not** implement temperature via `processTemperatureSamples` from Apple — Fitbit uses a REST pull, not HealthKit samples.
    **Do not** add business logic for threshold alerts — that is handled by `wearableService.recordReading()` which Plan 05 wires up.
